## 1. Checking field follows Event Settings

> "untuk 'checking' itu harus disesuaikan dengan event setting kalau memang belum mencapai state yang membutuhkan
> checking maka itu bisa di hide dulu."

- New Event Status flag **Checking Item** (`checkItem: boolean`, missing = false). Event Settings: column, KPI card and form
  field. Seed: **Finish setup** = true (all others false).
- Event Detail (cards, list view, item drawer): the **Checking** field is **hidden until the event has reached** (current or
  furthest stage) the **first** stage with `checkItem = true`.
- It can be **ticked / unticked only while the event is AT a stage with `checkItem = true`** and items are not locked
  (Checking Inventory or later). At other stages it is shown read-only.
- Before this change `checking` was a read-only seed value with no way to set it.
- Code: `isCheckItemStage()` in `src/lib/eventStatuses.js`; `itemFieldVisibility`, `canTickChecking`, `toggleChecking` in
  `src/pages/EventDetailPage.jsx`; `ItemCard` / `ItemTable` get `vis` and `onToggleChecking`.

## 2. Scan In / Scan Out follow Event Settings (and the scan rule is fixed)

> "scan in dan out begitu juga."

- **Scan In** row/column is hidden until the event reaches the **first** stage with `scan = "Scan"`.
  **Scan Out** is hidden until it reaches the **second** scan stage. (Seed: Waiting scan in / Waiting scan out.)
- **Scan rule changed** — the stage decides the phase, not the order of scans:
  - at the first scan stage a scan sets `scanIn` (button "Scan In", badge "Scanned in");
  - at any later scan stage a scan sets `scanOut` (button "Scan Out", badge "Scanned out").
  - "Waiting Scan" tab and the Next gate count lines missing the scan **of the current phase**
    (`scanIn` at the first scan stage, `scanOut` later). Before, `scanned: true` from scan-in let "Waiting scan out" pass
    without scanning out (gap reported in `docs/MOBILE-QA-ANSWERS.md` B9 — now fixed).
  - `scanned` is still set to true for compatibility; do not use it for logic.
- Code: `scanStageIdx`, `stageScanPhase`, `isScannedNow`, `doScan` in `EventDetailPage.jsx`.
- **Mobile:** use exactly this rule.

## 3. Event list: one Filter button → filter drawer

> "untuk filter saya mau di taruh di 1 tombol dan ketika dibuka muncul filter drawer nya saja."

- The inline filter row is gone. Next to the search box: **Filter** button (shows a count badge when filters are active).
- It opens a right-side **drawer** "Filter events": Location (multi), Event status / stage (multi), Start date from / to,
  Number of items (radio: Any, No items yet, Small 1–30, Medium 31–150, Large 150+). **Reset** clears the draft,
  **Apply** applies and closes. Changes are not applied until Apply.
- Active filters show as **removable chips** above the tabs with "N of M events" and **Clear all**. Filters apply to every
  tab and to the tab counts.
- Code: `filterOpen`, `draftFilters`, `applyFilters` in `src/pages/EventPage.jsx`; CSS `.btn-filter`, `.filter-chip`.

## 4. QR Type explained

> "qr type ini perlu diperjelas lagi fungsinya agar tidak membingungkan user."

- Event form field **QR Type** (required) is now two explained option cards instead of a dropdown:
  - **Individual** — "One QR label per item. Every item is scanned on its own. Best for small events or big single pieces
    (arches, sofas, screens)."
  - **Group (per box)** — "Items are packed into boxes and the QR label goes on the box. Scanning one box scans everything
    inside. Best for many small items (glasses, candles, flowers)."
  - Hint: "Decides how QR labels are printed and scanned for this event's items."
- Stored values: `qrType: 'INDIVIDUAL' | 'GROUP'` (same values as the production app's dropdown). The old web values
  (`scan_in`, `scan_out`, `scan_both`, `none`) are dropped; an event with an old/empty value must pick one before saving.
- Boxes are made in Event Detail ⋮ → Group Items; the box scan already scans every item inside.
- **[ASSUMPTION]** QR Type does not (yet) change any scan logic on web; it documents how labels are printed. Mobile/QR
  generator should print box labels for GROUP events and item labels for INDIVIDUAL events.

## 5. Event card: created date + photo-ready layout

> "tambahkan juga created at nya taruh di tempat yang proper, card kamu juga harus perhatikan agar ketika saya menggunakan
> image maka ini bisa terlihat dengan baik."

- Card footer meta line: **"Created 12 Mar 2026 · Updated: 9 Apr 2026"** (below date and location).
- Event field **`createdAt`** (ISO datetime): set when an event is created; all seed events have one.
- If the event has an **image**, the card shows a **16:9 cover** at the top (`object-fit: cover`, card corners clipped),
  so any photo size looks the same; cards without an image keep the same text layout.
- The event form image upload is resized before saving (max 1200 px JPEG) — `src/lib/imageUtils.js`.

## 6. Frozen Action column in every table

> "kalau di table ada action, maka wajib di freeze untuk action nya."

- Rule: any table whose **last header cell has class `col-action`** keeps that column pinned to the right while the table
  scrolls horizontally (`position: sticky; right: 0`, white background, soft left shadow; header stays above).
- Applied to all 20 tables with an Action column (Inventory, Warehouse, Warehouse Inventory, Area, Sub Area, Category, Unit,
  Event Status, Vendors, Users, Rent/Outsource items, Produced items, Event Inventory, Event Detail list view, Super
  Admin tables). **Rule for new tables:** put `className="col-action"` on the last `<th>` when it holds actions — no
  other code needed (CSS uses `table:has(thead th.col-action:last-child)`).

## 7. Images on Event Detail + event files

> "di event detail juga harus bisa mengakomodir jika ada image, buat supaya lebih mudah. di event user juga bisa upload
> file ya dimana nanti file akan ditampilkan di drawer."

**Item photos**
- Catalog item has a new field **`image`** (data URL, or a URL). Shown on Event Detail cards (140 px box, `object-fit: cover`,
  same height as the placeholder), as a 32 px thumbnail in the list view, and large in the item drawer.
- Easy upload: item drawer → **Upload photo / Change photo / Remove photo** (saved to the catalog item, so every event
  shows it). Also in Inventory → New/Edit Item → **Photo**.
- Photos are shrunk on upload (max 1000 px JPEG, ~100 KB) so they fit in browser storage.
- Code: `setItemImageByName()` in `src/lib/catalogStore.js`, `ItemImage`, `uploadItemPhoto` in `EventDetailPage.jsx`.

**Event files**
- Event Detail header button **Files (n)** opens the drawer **"Event Files"**: drop zone / Upload files (multiple), list with
  image thumbnail or file-type tile, name (click = download), size, uploader, date-time, delete.
- Limits: images any size (resized); other files ≤ 2 MB each (message otherwise). Storage-full shows a message.
- Store: `emi_event_files: { [eventKey]: [{ id, name, type, size, dataUrl, uploadedBy, uploadedAt (ISO) }] }` —
  `src/lib/eventFiles.js`. Activity log "Uploaded N file(s) to <event>".

## 8. Realistic mock data + cart warning on Next

> "berikan mock data lebih real lagi, kemudian pastikan jika ada barang yang belum di add dan masih ada di cart maka ada
> notifikasi ketika mau klik next."

**Mock data** (`src/data/events.js`, `src/data/inventory.js`)
- Every event now has a realistic name, description, venue **address**, **PIC**, **qrType**, **createdAt**; placeholder events
  were renamed (Wedding B → Wedding Andre & Clarissa, Wedding A → Akad Nikah Fajar & Laras, Super Grand Event Halo BCA →
  BCA Expoversary 2026, Event Music → Java Jazz Side Stage, Test rendy up → Sangjit Kevin & Mei, …). Event keys of renamed
  events changed; `data/productionSeed.js` updated.
- Demo cover images `public/demo/events/*.svg` (wedding, gala, corporate, festival, garden, beach) on most events, and demo
  item photos `public/demo/items/*.svg` on 52 of 98 items — so both "with photo" and "without photo" layouts are visible.
- Browsers that already stored the catalog (`emi_catalog`) keep their stored copy; clear storage to see the new seed.

**Cart warning**
- Clicking **Next** (or picking a later stage) while the cart still holds items opens **"Items in the cart are not added
  yet"**: count + pcs, list of up to 8 cart lines (name, qty, area or "no area"), buttons **Cancel**, **Continue without
  them** (cart is kept), **Open cart** (opens the picker/cart). Going back to an earlier stage is not interrupted.
- Code: `cartWarnStage`, `requestStageChange(step, { skipCartCheck })` in `EventDetailPage.jsx`.
