# PRD — EMI — changes of 2026-11-12 (rounds R39–R42)

> For developers (web + mobile). Builds on `PRD-TECHNICAL-SYSTEM-SCHEMA.md` and `PRD-2026-11-11.md`.

## 1. Event Status flag "Allow Add Item"

> Owner: "tambahkan opsi juga untuk allow add item, jadi kalau allow maka user masih bisa add dan kalau no maka user sudah
> tidak bisa add item lagi. tujuannya untuk menjaga agar tidak ada penambahan di akhir."

- Field `allowAddItem: boolean` on each Event Status. **Missing = true** (status lists saved before this keep working).
- Event Settings (Event Status page): column **Allow Add Item** (between Check Ownership and Allow Delete), KPI card,
  form field True/False with the hint "When False, nothing can be added to an event at this status…".
- Event Detail, while the event is at a stage with `allowAddItem = false`:
  - **Add Item** button disabled (tooltip: `Adding items is off at "<stage>" (Event Settings → Allow Add Item)`);
  - **Rent Item, Outsource Item, Request Production** hidden; "Create Production" on a broken item disabled;
  - lock note: `Adding items is off at "<stage>" (Event Settings → Allow Add Item = False). Rent, Outsource and Production
    requests are off too.`
- It is **per current stage**: going back to a stage with True allows adding again (unlike Stock Return, which locks for
  good once reached). Both rules combine: `addLocked = stockReturnReached || !allowAddItem(current stage)`.
- **[ASSUMPTION]** "add item" covers Rent / Outsource / Production, since those also add lines to the event.
- Seed (`src/data/eventStatuses.js`): False for Waiting scan in, Event running, Waiting scan out, Finished; True elsewhere.
- Code: `isAddAllowedStage()` in `src/lib/eventStatuses.js`; `stockReturnLocked`, `addNotAllowedHere`, `addLocked` in
  `src/pages/EventDetailPage.jsx`; `src/pages/EventStatusPage.jsx`.
- Backend: `POST /events/{id}/items`, `/rentals`, `/outsource-orders`, `/productions` → `409 ADD_NOT_ALLOWED_AT_STAGE`
  when the event's current stage has `allowAddItem = false`.
- Mobile: hide/disable every "add" entry point with the same rule.

Verified: lint 11, build OK; Chromium — Product Photoshoot Kilau (Waiting scan in) Add Item disabled with the lock note;
Intimate Dinner Ubud (On preparing items) Add Item enabled; Event Status table shows the new column.

## 2. Cutting Stock (R40) — stock is deducted and reserved when the event enters that stage

> Owner: "tambahkan 1 lagi untuk cutting stock, artinya jika sudah enable maka ketika masuk ke fase itu stok akan dianggap
> sudah berkurang dan di reservasi untuk event tersebut. pastikan sebelum klik next di event detail nya harus ada penjelasan
> yang jelas dan ada ilustrasi atau icon agar membuat user notice."

Supersedes the 2026-10-05 decision that removed Cutting Stock from Event Settings.

**Event Settings**
- Columns **Cutting Stock** and **Stock Return** (before Production Item), KPI card "Cutting Stock", form fields with help.
- Exclusive: only one status may have Cutting Stock, only one Stock Return, and never the same status (the form disables
  "True — already used by <status>" and switching one on switches the other off on that status).
- Seed: Cutting Stock = **Waiting scan in** (loading), Stock Return = **Waiting scan out** (unloading).

**What happens** (`src/lib/eventStockCuts.js`)
- Moving FORWARD into (or across) the Cutting Stock stage: every event line from our stock (`warehouseItem` and not
  rented/outsourced) that is not cut yet is deducted from its Warehouse Inventory row — the row of the line's
  `warehouse`, else the row of that item with the most stock. Ledger: reason **"Event cut"**, note
  **"Reserved for <eventKey>"**, stage, user. If a row has less than the line qty, only what exists is cut and the
  shortfall is reported.
- The cut is remembered in `emi_event_stock_cuts[eventKey][lineId] = { rowId, warehouse, qty, cutAt, returnedQty?, returnedAt? }`
  so a reload never cuts twice (lines get `stockCut` back from it on load).
- Moving forward into the Stock Return stage: each cut line gets back `qty − brokenWrittenOff` (broken units written off in
  the same move included). Ledger **"Event return"**. After it, adding items stays locked (existing rule).
- Going back never restores stock. Warehouse Inventory rows show an orange chip **"N in events"** for stock that is cut and
  not returned yet.

**Making the user notice** (`src/components/StockMoveNotice.jsx`)
- Banner above the item list while the NEXT stage cuts (or returns) stock: box icon with a soft pulse,
  "**Next stage cuts stock** — moving to "<stage>" deducts N pcs (M items) from the warehouses and reserves them for this
  event." + "What happens?" (opens the Next flow).
- Confirm popup: illustration **Warehouse → (−N pcs, animated dots) → This event**, title "Stock will be cut and reserved for
  this event", explanation, per-warehouse list (−qty), red warning for pcs not in stock, footer "Going back to an earlier
  stage does not restore it. The stock comes back at "<return stage>" (Stock Return). Rented and outsourced items are not
  cut." Button **Confirm & Cut Stock**. The return popup is the green mirror (This event → Warehouse, broken pcs warning).
- Animations respect `prefers-reduced-motion`.

**Backend:** `POST /events/{id}/advance` must create the "Event cut" / "Event return" movements atomically and store the
per-line reservation; `GET /warehouse-inventory` should return `reservedQty` per row.
**Mobile:** show the same banner and the illustrated confirm before Next; never cut client-side.

Verified (R40): lint 11, build OK; Chromium — Engagement Rina & Bayu at Finish setup shows the banner (153 pcs, 8 items);
Next → Check ownership → confirm with illustration (Bali 66 −94, Surabaya −30, Bali 70 −29) → 8 "Event cut" movements in the
ledger, 8 "Stock cut" badges, still 8 after reload (no double cut); Event Status shows both new columns.

## 3. Event Settings redesign (R41)

> Owner: "kalau kamu lihat di event setting sudah sangat panjang tolong perbaiki UI nya agar tetap rapi" (as head of
> engineering, design, creative and product).

Problem: 12 True/False columns, 11 KPI cards and a 9-sentence paragraph — the table scrolled sideways and the important
rules (stock, locks) drowned in "False" badges.

**Single rule model** — `RULES` / `RULE_GROUPS` in `src/pages/EventStatusPage.jsx` define every stage rule once (field,
group, label, chip text, description, default). Table, legend and form all read it, so a new rule is added in one place.

| Group (colour) | Rules (chip) |
|---|---|
| Scanning (green) | Scan |
| Stock (orange) | Cut stock, Return stock |
| Items (blue) | Checking, Ownership check; **No adding** / **No deleting** (red, shown only when the default-allowed rule is OFF) |
| Requests (purple) | Production, Rent, Outsource |

**Page**
- Header: title + one-line intro + **"What do the rules mean?"** → legend card (each group, chip + description).
- Summary: 3 KPIs (Stages, Scan stages, Events running) + a Stock card ("Cut at Waiting scan in · Return at Waiting scan
  out"), and a **pipeline strip** of all stages in order with small dots (green = scan, orange = stock move, red = no adding).
- Table: Order (reorder arrows appear next to the number in Edit Order mode), Status (+ code tag), **Rules** (chips; "No
  special rules" when none), Events, Updated, Action (frozen). The separate "Edit Order" column and the duplicate "New"
  button are gone (New Status stays top right).
- Form (wide modal): Order / Name / Code in one row, then the four groups as **switches** with a one-line explanation each.
  Cutting Stock / Stock Return stay exclusive: the switch is disabled with "Already used by "<stage>". Turn it off there
  first."; turning one on turns the other off on the same stage.
- Responsive: KPIs wrap to 3 + 1, pipeline scrolls sideways, form fields stack.

Data and behaviour are unchanged (same fields as before). Verified: lint 11, build OK; Chromium 1400 px (no sideways scroll,
9 rows fit one screen), edit form with grouped switches and the disabled Stock Return switch, 390 px layout.

## 4. Closing flow: Ready for Checking → For Return → Partial Return (R42)

> Owner: "ketika sudah selesai finish akan masuk ke ready for checking. di ready for checking user sudah tidak bisa add barang
> apa apa lagi ke event. dan list item akan memiliki tombol checked dan note … jika sudah selesai semua di check maka main
> action akan berubah menjadi for return. ketika diklik akan ada confirm bahwa stock akan dikembalikan seperti semula. akan ada
> kondisi dimana bisa jadi barang itu belum selesai diambil semua maka nanti status event nya akan menjadi partial return."

### 4.1 States (closing status of an event)
| Stored value | Label | Main action on Event Detail |
|---|---|---|
| `on-going` at the finished stage | Ready to Close | **Start Checking** (replaces Next) |
| `checking-inventory` | **Ready for Checking** (renamed from "Checking Inventory") | **For Return** — disabled until every item is Checked (`For Return · 12/58 checked`) |
| `partial-return` (new) | **Partial Return** | **Return remaining (N pcs)** |
| `returned-completed` | Returned & Completed | — (view only) |
| `transferred` | Transferred | — (every line was transferred, nothing returned) |

The **finished stage** = the Event Status with the new rule **Ready for checking** (`closeStage: true`, one stage only; seed:
**Finished**). Fallback: the last stage. Postphone / Disable come after it and are not the normal flow
(`getClosingStageName()` in `src/lib/eventStatuses.js`; `isReadyToClose` in `src/lib/eventClosing.js`).

### 4.2 Start Checking
Popup "Start checking this event?" with the 3 steps (1 Ready for Checking · 2 For Return · 3 Returned & Completed /
Partial Return) and "After this, nothing can be added to this event (no Add Item, Rent, Outsource or Production), and items
can no longer be modified or deleted." → closing = `checking-inventory`, list opens on **Not checked**.

### 4.3 Ready for Checking
- Nothing can be added: `addLocked` is true whenever closing ≠ on-going (Add Item disabled; Rent / Outsource / Production
  hidden). Modify / Delete stay hidden (existing lock).
- Blue progress panel: "Ready for Checking · X of Y items checked" + bar + **Check all** (confirm) + one-line instruction.
- Tabs **Not checked (n)** and **Checked (n)** next to All.
- Every card: footer with **Mark checked / Checked** (green when on, toggles) and **Note / Edit note**; the note shows as a
  yellow 📝 line. List view: compact Check + Note buttons in the frozen Action column. Item drawer shows "Checked (closing)",
  "Check note", "Returned".
- Note popup: "What should others know about this item?" (e.g. "2 chairs scratched · 1 box still at the venue").
- The preparation "Checking" tick box (Checking Item rule) is hidden during closing so the two are not confused.
- Rented / outsourced lines are also checked, but they go back to their vendors via the Rented / Outsourced tabs.

### 4.4 For Return
- Popup (wide) "For Return — put the stock back":
  - If stock was cut (Cutting Stock stage): the green illustrated notice **This event → Warehouse (+N pcs)** with per-warehouse
    totals — "stock goes back as it was".
  - If no stock was cut: "Stock was not cut for this event…, so warehouse numbers don't change. Confirm what is physically back."
  - Table of stock lines: Item (+ area, broken written off, check note), Warehouse, **Out**, **Back now** (number, default = Out,
    shows "N still out" when lower), **Transfer** (moves the whole line to another on-going event, as before).
  - Buttons: Cancel · **Everything is back** (fills all) · **Confirm return** / **Confirm partial return**.
  - Orange warning when something stays out: "N pcs are not back yet. The event becomes Partial Return…".
- Out per line = (cut qty, or line qty if not cut) − broken units written off − already returned.
- Confirm: cut lines get `Event return` stock movements for the returned pcs (`returnStockParts` in `lib/eventStockCuts.js`,
  partial allowed); per line `returnedQty` / `returnedAt` are stored; complete lines get `resolution: 'returned'`.
  Result: something still out → **Partial Return**, else **Returned & Completed** (or Transferred if nothing was returned).
- Partial Return: orange panel "N pcs of M items still out" and main action **Return remaining (N pcs)** → same popup with only
  the outstanding lines.

### 4.5 Storage
`emi_event_checking = { [eventKey]: { [lineId]: { checked, checkedBy, checkedAt, note, returnedQty, returnedAt, transferredTo } } }`
(`src/lib/eventChecking.js`), merged into the lines on load so a reload keeps checks, notes and returns. Cut stock records keep
`returnedQty` too (`emi_event_stock_cuts`). Stock Return as a stage rule is now **optional** (off in the seed): normally the stock
comes back at For Return.

### 4.6 Demo data
- Rooftop Sunset Mixer: at **Finished** → shows **Start Checking**.
- Harvest Festival Bazaar: Ready for Checking, ~80 of 140 checked, with notes.
- **Summit Afterparty**: Partial Return — 3 lines (Gold Rim Dining Chair, Gold Geometric Centerpiece, Large Round Candle
  Holder) still partly out (48 pcs).
- Event list: new tab **Partial Return**; "Checking Inventory" tab/KPI renamed **Ready for Checking**.

### 4.7 Backend / mobile
- `POST /events/{id}/start-checking` (only at the closeStage), `PATCH /events/{id}/items/{lineId}/check {checked, note}`,
  `POST /events/{id}/return {lines:[{lineId, qty}]}` → stock movements + status `PARTIAL_RETURN | RETURNED_COMPLETED`.
- Mobile: the checking screen is a natural mobile task — big Checked toggle + Note per item, Not checked filter, For Return
  only when all are checked.

Verified (R42): lint 11, build OK; Chromium — Rooftop Sunset Mixer: Start Checking → popup → Ready for Checking (Add Item
disabled, tabs Not checked 58 / Checked 0, "For Return · 0/58 checked" disabled) → check + note → Check all → For Return
(51 stock lines) → one line set to 0 → "Confirm partial return" → Partial Return, survives reload → Return remaining → Returned &
Completed. Summit Afterparty shows 48 pcs of 3 items still out; event list has the Partial Return tab.
