## 1. Add items (and vendors) straight from the request forms

Owner: "ketika di event detail, ketika user mau meminjam atau memproduksi user bisa langsung menambahkan
barang dari situ (cek dulu sudah ada belum) … jadi user tidak perlu mengisi dulu di master data".

- **Before:** Rent Item had a free-text item field (catalog names only as suggestions; nothing saved to
  master data). Request Production had a free-text name; a new item only reached master data when the
  production was Done (as a "Needs setup" draft).
- **Now** (`src/components/QuickPickers.jsx`):
  - `CatalogItemPicker` — a searchable list of Inventory master data (name, SKU, stock). Typing shows the
    items that already exist ("check first"). If it isn't there, the last row
    **"+ Add “<typed text>” as new item"** opens the normal New Item form (`ItemFormModal`, title
    "New Item (master data)") on top, with the name and a free SKU (`suggestSku`, e.g. ISS-001) pre-filled.
    Saving adds the item to master data immediately (no opening stock) and selects it. The form still refuses
    a name or SKU that is already used.
  - `VendorPicker` — only vendors of the matching kind (see §2), with **"+ Add “…” as new … vendor"**
    which opens `VendorFormModal` for that kind and saves the vendor into that menu's list.
- Used in: Event Detail → **Rent Item**, **Outsource Item** (item + vendor), **Request Production → New
  Production** (item + vendor, vendor list still filtered by Internal / External), and Rent → Rented Items →
  New Rental. New items get `source` = `'rent'` / `'outsource'` / `'production'` on the catalog record.
- Rented / outsourced items created this way sit in master data with 0 stock. They are still never our stock:
  receiving them only adds an event line (ownership Outsource).
- `SearchableSelect` got an optional `onCreate(query)` + `createLabel` prop (the "+ Add" row).
- `Modal`: Escape now closes only the top-most modal, and does nothing while a dropdown is open
  (before, Escape in a dropdown also closed the form behind it).

## 3. Outsource (new) — works exactly like Rent

Owner: "tambahkan juga event setting untuk outsource, dan buatkan menunya juga di nav kiri. outsource sama
seperti rent juga konsepnya".

- **Event Status** (Event Settings) has a new flag **Outsource Item** (`outsourceItem`): column, KPI card and
  form field. Statuses saved before this existed follow their Rent Item flag (`isOutsourceStage` in
  `lib/eventStatuses.js`); the seed sets it equal to `loanItem`.
- **Event Detail**: at a stage with the flag, button **Outsource Item** (opens the same form as Rent Item, with
  outsource wording) and tab **Outsourced**. Lifecycle Requested → **Received** (adds the item to the event,
  ownership Outsource, `fromOutsource: true`) → **Completed**; Overdue when past the "Until" date.
- **Menu**: Master Data → **Outsource** (`/outsource`), tabs **Vendors | Outsourced Items**; vendor detail
  `/outsource-vendor-detail?id=`. No Internal / External (always outside). Same delete guard as Rent
  (blocked while an order is Requested or Received). No "New" button on Outsourced Items: outsourcing is
  per event **[ASSUMPTION]**.
- **Code**: the rent module is reused with `kind = 'outsource'` — `lib/eventLoans.js` (`KIND_TEXT`,
  `kindText()`, `statusLabels()`, every getter/saver takes `kind`), `EventLoans.jsx`, `LoanLogTab.jsx`,
  `LoanVendorDetailPage.jsx`, `VendorPage.jsx` (`CONFIG.outsource`). Storage: `emi_event_outsource`
  (per event), `emi_outsource_general` (unused for now). Stored statuses are the same values as rent
  (`Requested` / `Borrowed` / `Returned`); only the labels differ.
- **Seed**: outsource vendors ids 101–103 (Bali Florist Collective, Videotron Nusantara, Kru Rigging Profesional),
  appended once to vendor lists saved earlier (`emi_vendors_outsource_seeded`); 6 outsource records on 4 events
  (`SEED_EVENT_OUTSOURCE` in `data/eventLoanSeed.js`).
- Not yet included: outsource cost in Event Report / Dashboard / Global Search (they still show rentals only).

## 5. R36 — Rent vs Production: who owns the item

Owner: "rent sifatnya ketika barang sudah selesai akan dikembalikan, beda dengan production: kalau production
barang selesai maka akan menjadi asset kita".

- **Rent** = temporary. Received → used → **returned to the vendor** (Mark Returned). Never our stock, never in
  asset value. Event lines from a rental carry `fromLoan: true` and a blue **Rented** badge.
- **Production** = ownership. Done → `stockInProduced()` adds the qty to the deploy-to warehouse, so it **becomes our
  asset** (Warehouse Inventory, Total Asset Value). Event lines carry `fromProduction: true`.
- **Outsource** = like rent (not our asset); badge **Outsourced** (`fromOutsource: true`).
- The Rent Item form and the Request Production notice now say this in plain words.

## 7. R36 — A past event can't be edited

Event list (`EventPage.jsx`): the Edit button is disabled (tooltip "The event date has passed…") and `openEdit` refuses
when the event's last day (latest of finish / start / event date) is **before today**. Today = the app's mock
`TODAY` (2026-04-09, `data/events.js`), like every other date rule in the app. Events in "Returned & Completed" were
already read-only. **[ASSUMPTION]** This covers the event's own data (name, dates, location …); Event Detail item work
(scan out, returns) after the event is still allowed because the after-event stages need it.

## 8. R36 — Finish Date ≥ Start Date

Event form: Finish Date input has `min = Start Date`; a Finish Date before the Start Date shows
"Finish Date can't be before Start Date" and Save is disabled. Seed event "Test rendy up" had finish < start; fixed to
2026-01-07. (Rent / Outsource forms already enforce "Return by / Until ≥ from".) Event Date (load-in) is not limited.

## 9. R36 — Modify Item

Event Detail → Modify Item:
- **Area / Sub Area** (location) can always change.
- **Quantity** can change only if the item was added at the **current** stage (`item.stage` = current stage, the
  "Added New" tab). For items from an earlier stage the field is disabled with the hint
  "Added at "<stage>" (an earlier stage): only the location can change."
- Ownership, PIC and Note are shown read-only (ownership still changes via its badge / Check Ownership flow).
