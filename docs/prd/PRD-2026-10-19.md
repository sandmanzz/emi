## 1. "Loan" is now called "Rent"

- Every user-facing "Loan / Borrow / Borrowed" text is now **Rent / Rented**. Concept unchanged: **we rent items
  from a vendor**; we never lend our items out.
- Menu: Master Data → **Rent** (`/rent`). Tabs: **Vendors** | **Rented Items** (`/rent?tab=items`).
  Vendor detail: `/rent-vendor-detail?id=`. Old URLs `/loan`, `/loan-vendor-detail`, `/item-loan*` still work (redirect).
- Event Detail button "Rent Item", tab "Rented". Event Status flag label "Rent Item".
- **Code names did NOT change** (to keep stored data valid): vendor kind `'loan'`, stage flag `loanItem`,
  files `lib/eventLoans.js`, `LoanLogTab.jsx`, `LoanVendorDetailPage.jsx`, localStorage `emi_event_loans`, `emi_rentals`.
- Status value stays `'Borrowed'` internally; it is **displayed** as "Rented" through
  `LOAN_LABEL` in `lib/eventLoans.js` (`{ Requested, Borrowed: 'Rented', Returned, Overdue }`). Always display via `LOAN_LABEL`.

## 2. Vendor menus and form

- Master Data → **Production** (`/vendor`, was labelled "Vendor"). Tabs: Vendors | Produced Items.
- The vendor form has **no "Vendor type" checkboxes** any more. The menu decides the kind: a vendor created in
  Rent gets `kinds: ['loan']`, in Production gets `kinds: ['production']`. Editing keeps the vendor's existing kinds
  (a vendor that is in both lists stays in both).
- **Rent vendors have no Internal / External**: hidden in the form, the list (no Type column, no origin filter; the
  stat cards are Total Vendors / Rentals / Active Rentals) and the rent vendor detail. New rent vendors are stored with
  `origin: 'External'`. **[ASSUMPTION]** Production vendors keep Internal / External (the owner asked for it on
  2026-10-16 and production pickers use it). If the owner meant "remove it everywhere", remove it from Production too.

## 3. A vendor with active records cannot be deleted

- Rent vendor: blocked while any of its rentals (event or warehouse) is **Requested** or **Rented** (`Borrowed`).
- Production vendor: blocked while any of its productions is not **Done** (Requested / In Production).
- The delete dialog then says how many active records there are and only offers **Close**. Same rule for
  "Remove from this list" (vendor in both lists). The list shows "N active" under the record count.
- **[ASSUMPTION]** The owner said "requested"; we also block Rented / In Production because the item is still out.

## 4. Warehouse Inventory

- The **Production tab is removed**. Productions are managed in Master Data → Production → Produced Items
  (same `ProductionLogTab`, it still stocks finished items into the deploy-to warehouse).
- New **source filter** in the Inventory tab: All Sources / **Normal** / **Produced** / **Rent**.
  - Produced = the item name has a Done production (`getAllProductions()`), or catalog `source === 'production'`.
    Those rows show a green "Produced" badge.
  - Rent = warehouse rentals (`getGeneralRentals()`) with status Rented and a warehouse. They are shown as **read-only
    virtual rows** (purple "Rent" badge, vendor, due date, Rented/Overdue badge, link to Rent → Rented Items).
    They appear in "All Sources" and "Rent", never count in Total Items / Safe / Warning / Critical or asset value,
    and have no Edit / Delete.
  - Normal = every other real row.
- New **Total Asset Value** card at the top = Σ `totalValuation` (valuation × warehouse stock) of all real rows.
  When a filter is active, a "Current filter" value is shown on the right. Rows without a valuation are counted
  in an orange hint.
