## 2. Inventory — Item Value and asset value (R28)

**Goal:** know what the inventory is worth.

- **Data:** every catalog item (`src/data/inventory.js`) has `itemValue`: integer Rupiah **per unit**.
- **Inventory listing (`/inventory`):**
  - Columns **Item Value** and **Total Value** (`itemValue × totalStock`). Both are sortable.
  - A **Total Asset Value** card: Σ(itemValue × totalStock) over all items. When a filter is active, it
    also shows the filtered total. A `<tfoot>` row shows the filtered total too.
  - Items without `itemValue` show "Not set", count as 0, and the card says how many there are.
  - [ASSUMPTION] "total nilai asset … dibaca dari sum item value" = Σ(value × stock), not Σ(value).
- **Category filter is multi-select** (checkboxes, count per category, Clear). Empty = all categories.
  It's built with the `multiple` prop of `src/components/SearchableSelect.jsx` (value = array).
  [ASSUMPTION] Multi-select is for the filter only. An item still has exactly one `category`.
- **Inventory Detail (`/inventory-detail?id=`)** reads the shared catalog (`getCatalog()`). It shows
  Item Value, Total Value and a **Production History** table for the item.
- Warehouse Inventory rows have `valuation` = the same unit value, and `totalValuation = valuation × itemStock`.
  The two fields are **not linked live** (§9 Q3).

**Acceptance:** with no filter, the card shows Rp1.367.910.000 (seed). Selecting Floral + Lighting shows 26 items.

## 3. Production (R28)

### 3.1 Warehouse Inventory → tab **Production**
One table with **every production record**, from two sources:

| Source | Created where | Can change status here? | On **Done** |
|---|---|---|---|
| `event` | Event Detail → Request Production (only at stages with `productionItem: true`) | No ("Update in Event Detail") | Item added to the event. A catalog draft is created only for unknown items. |
| `manual` (restock) | This tab → **Record Production** | Yes: Requested → Start → In Production → Mark Done; Cancel only while Requested | **qty added to the deploy-to warehouse row** + Stock History line `reason: 'Production'`. If the row is missing, it is opened at 0 first. An unknown item becomes a "Needs setup" draft. |

- Record Production fields: item (existing catalog item **or** new name), qty ≥ 1, deploy-to warehouse
  (not "Buy"), made by Internal/External + a vendor of kind `production`, note.
- Filters: search, status, source, warehouse. KPIs: records, in progress, done, qty produced.
- `finishedAt` (YYYY-MM-DD) is set when a record becomes Done (both sources).
- The same component (`ProductionLogTab`) is the **Produced Items** tab of the Vendor menu (§5).

### 3.2 Storage
- Event productions: `localStorage.emi_production_requests[eventKey]`, seed `SEED_EVENT_PRODUCTION`
  (`src/data/productionSeed.js`).
- Restock records: `localStorage.emi_production_log`, seed `SEED_MANUAL_PRODUCTION`.
- `getAllProductions()` in `src/lib/productionRequests.js` merges both (convert requests are excluded)
  and adds `uid`, `source`, `eventKey`, `eventName`.

## 4. Event Status (Event Settings) — new per-stage flags (R29, R30)

### 4.1 Flag table (all on `/event-status`, each has a column, a KPI card and a True/False form field)

| Field | Label | Default when missing | Seed True on | Effect on Event Detail while the event is AT that stage |
|---|---|---|---|---|
| `scan` | Scan | 'None' | Waiting scan in, Waiting scan out | Scan buttons; Next blocked while items are unscanned (pre-existing) |
| `productionItem` | Production Item | false | On preparing items, Finish setup | "Request Production" button (pre-existing) |
| `checkOwnership` | Check Ownership | false | Finish setup | Asks about ownership change before Next (pre-existing) |
| **`allowDelete`** | **Allow Delete** | **true** | Created by admin up, On preparing items, Finish setup, Postphone, Disable | When **false**: no delete button on item cards/rows. The drawer shows "Delete is off at "<stage>"". `deleteItem()` refuses too. |
| **`loanItem`** | **Borrow Item** | **false** | Created by admin up, On preparing items, Finish setup | "Borrow Item" button (§4.2) |

- Helpers in `src/lib/eventStatuses.js`: `isDeleteAllowedStage(name)` (missing field = true), `isLoanStage(name)`.
- [ASSUMPTION] "allow delete option" = whether **items** may be deleted at that stage, not deleting the status row.
- [ASSUMPTION] "option untuk meminjam barang" = a per-stage flag that enables **Borrow Item**, like Production Item.
- The existing lock is unchanged: from Checking Inventory onward items can't be modified or deleted at all.

### 4.2 Borrow Item (event borrows / rents from a loan vendor)
- **Where:** Event Detail header button **Borrow Item** (only when `loanItem` is true, the event is On Going
  and Add Item isn't locked) and a **Borrowed** tab, shown when the flag is on or the event has loans.
- **Form:** item name (free text + catalog suggestions; it may be outside our catalog), qty ≥ 1, unit,
  Area (required), Sub Area, loan vendor (vendors with kind `loan`, required), borrow from date,
  return-by date (≥ from), rental cost per unit (optional, Rp), note.
- **Lifecycle:** `Requested` → **Mark Received** → `Borrowed` → **Mark Returned** → `Returned`.
  - Mark Received adds the item to the event (`ownership: 'Outsource'`, `warehouseItem: false`,
    `fromLoan: true`, `loanVendor`), stamped with the current stage. Drawer Source reads "Borrowed from <vendor>".
  - Cancel is only allowed while Requested.
  - **Overdue** is a display status: Borrowed and `dueDate < TODAY`.
- **Storage:** `localStorage.emi_event_loans[eventKey]`, seed `src/data/eventLoanSeed.js` (19 records over
  10 events). Helpers in `src/lib/eventLoans.js`: `getEventLoans`, `saveEventLoans`, `getAllEventLoans`,
  `loanDisplayStatus`, `loanTotalCost` (qty × rentalCost).
- No warehouse stock changes: borrowed items are not ours.

## 5. Vendors: two CMS menus, two tabs each (R28, R30)

### 5.1 Vendor model (`src/lib/vendorStore.js`)
`{ id, name, origin: 'Internal'|'External', kinds: ('production'|'loan')[], description, phone, address }`
- `kinds` decides which menu lists the vendor and which pickers offer it
  (Request Production / Record Production → `production`; Borrow Item → `loan`).
- Records saved before a field existed are normalised on read: `contact`→`phone`, `type`→`description`,
  missing `kinds` → both.
- `getVendorsOfKind(kind)` is the filter to use. Seed: 19 vendors (ids 1–5 loan, 6 both, 7–14 production, 15–19 loan).

### 5.2 Menus (one component, `src/pages/VendorPage.jsx`, prop `kind`)

| Menu | Route | Tab 1 **Vendors** | Tab 2 | Row click |
|---|---|---|---|---|
| Master Data → **Vendor** | `/vendor` (`?tab=items`) | CRUD list of `production` vendors + Productions count | **Produced Items** = `ProductionLogTab` (same as §3.1) | `/vendor-detail?id=` |
| Master Data → **Loan** | `/loan` (`?tab=items`) | CRUD list of `loan` vendors + Loans count | **Borrowed Items** = `LoanLogTab` (all event loans, read-only, filters status/vendor/search) | `/loan-vendor-detail?id=` |

- Form (`VendorFormModal`): name*, Internal/External*, Vendor type* (Production / Loan checkboxes,
  default = the menu it was opened from), description, phone, address.
- Delete: if the vendor has both kinds, it is only **removed from this menu's list** (its kind is dropped);
  otherwise the vendor is deleted. Old records keep the `vendorName` they were saved with.

### 5.3 Detail pages
- **`/vendor-detail`** (production): profile; KPIs (productions, events served, qty produced, in progress);
  Items Produced (per item: done / total qty and events); value of finished production (qty × current
  Item Value); Production History; Item Loans the vendor borrowed from us, if any.
- **`/loan-vendor-detail`** (loan): profile + events served + total rental cost; Items Borrowed (per item:
  total qty, qty out now, events); Loan History (`LoanLogTab` filtered to the vendor); our items lent to
  this vendor (Item Loan), if any.

## 7. Event Report — rewritten (R30)

- **Route:** `/event-summary?name=<event key>` (a plain upper-case name is also accepted). Sidebar:
  Report → **Event Report**. Linked from the Event list "Summary" icon and the Event Detail summary modal.
  With no `?name=`, the event with the most items opens.
- **Design goal:** stay fast and readable with **hundreds of item lines** (tested with 312 lines: about 0.5 s to load,
  about 0.5 s to render all rows).
- **Sections:**
  1. Header: event picker (all events), **Export CSV** (filtered rows), **Print**.
  2. Event strip: name, code, dates, location, "Stage x/y: name" or "Event finished", status badge, Open Event Detail.
  3. KPIs: Item lines (+ total pcs), Value in use (short Rp, full value in the sub line), Checked %, Scanned in %,
     Scanned out %, Broken (lines + pcs).
  4. **Progress by Area** table: sortable (area, lines, qty, value, checked %, scan in %, scan out %, broken),
     inline bars. Clicking a row toggles that area in the item filter.
  5. Breakdown cards: Progress, Ownership, Category, Added at stage.
  6. **Items** table:
     - Toolbar: search (deferred), area multi-select, progress, owner, category, Clear filters, Group by area (on by default).
     - Sortable columns. Sticky header in a scroll box (max 70vh). Group header rows with subtotals.
     - Rows per page 25 / **50** / 100 / All. First/prev/next/last.
- **Progress of an item** (one value, first match wins): Broken (`brokenQty > 0`) → Scanned out (`scanOut`) →
  Scanned in (`scanIn` or `scanned`) → Checked (`checking`) → Not checked. A ✓ marks cross-checked (`checked`).
- **Value** = qty × catalog `itemValue` (0 when the item is not in the catalog).
- **Print** renders all filtered rows (not just the page) with print CSS that hides the header/sidebar/toolbars.
- **CSV columns:** No, Item, SKU, Category, Area, Sub Area, Qty, Unit, Unit Value, Total Value, Ownership, Added at stage,
  Progress, Checking, Scan In, Scan Out, Cross-checked, Broken qty, PIC, Note.
- **Performance rules:** enrich items once (`useMemo`), compute all aggregates in one loop, render only the current
  page, `useDeferredValue` for search. Don't add per-row lookups inside render.
