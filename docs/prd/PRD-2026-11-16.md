# PRD — EMI — changes of 2026-11-16 (round R44)

> For developers (web + mobile). Builds on `PRD-TECHNICAL-SYSTEM-SCHEMA.md` and `PRD-2026-11-12.md` (§4–§5 closing / transfer).

## 1. Return form: event name no longer cut off
> "untuk return form, bagian event name masih terpotong"

The Transfer box was squeezed inside the Item column. It now opens as its **own full-width row** under the item (light purple),
laid out as: title → event select (full name + current stage as meta) → "Currently at <stage> (step n of m)" → stage select →
"Quantity to transfer [n] of N out" → Transfer N pcs / Cancel. Select labels wrap instead of being cut.

## 2. Transferred information everywhere
> "pastikan ketika barang ditransfer harus ada informasi transferred"

- Return row: under the item, one line per transfer: "↗ 5 transferred → **Wedding Spring Garden** (Created by admin up)".
- Popup footer block **"Transferred from this event"** listing every transfer (item, pcs, target, stage), also for lines that are
  fully transferred and no longer in the table.
- Source event cards/list: badge **Transferred N** (+ "(part)"), tab **Transferred (n)**, drawer rows "Transfer 1: …".
- **Receiving event:** the new line carries `transferredFrom` / `transferredFromName` → badge **Transferred in** on card and list,
  drawer row "Transferred in from <event>", note "Transferred from <event>".

## 3. Item photo can't be changed in Event Detail
> "di barang detail di event detail itu harusnya image tidak boleh diganti disitu"

Reverses 2026-11-11 §7: the drawer's Upload / Change / Remove photo is removed. The drawer shows the Inventory photo with the hint
"Photo from Inventory. To change it, edit the item in Inventory." Photos are managed only in Inventory → New / Edit Item.

## 4. Rent, Outsource and Production in sync with the main menus
> "antara outsource, rent, production harus sync dengan data yang ada di main navbar"

- Both places already read the same stores (`emi_event_loans`, `emi_event_outsource`, `emi_production_requests`), but the menus
  could only show event records ("Update in Event Detail"). Now the menus can act on them too, with the **same rules**:
  - Rent → Rented Items / Outsource → Outsourced Items: **Cancel** (Requested), **Mark Received**, **Mark Returned / Completed**.
    Mark Received is refused when the event is already in checking ("nothing can be added").
  - Production → Produced Items: **Start**, **Mark Done** (stock goes into the deploy warehouse = our asset).
- Received / done from a menu → the item is queued for the event (`lib/movedItems.js`) with its flags (`fromLoan` /
  `fromOutsource` / `fromProduction`, vendor, warehouse) and appears on Event Detail with the right badge next time it opens.
- Code: new `src/lib/eventRecordActions.js` (`advanceEventRental`, `cancelEventRental`, `advanceEventProduction`,
  `eventAcceptsChanges`), used by `LoanLogTab.jsx` and `ProductionLogTab.jsx`; Event Detail's incoming merge keeps the flags.
- Backend: one endpoint per action (`POST /rentals/{id}/receive|return`, `POST /productions/{id}/start|done`) called from both
  screens; the event line is created server-side.

Garden rental → Event Detail "Rented 4" with a Rented badge on the new line; Production menu Start on an event production works.
