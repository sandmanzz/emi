## High

### 1. Double booking
- **Scenario:** Wedding A (12 Jul) and Corporate Gala (12 Jul) both add 200 Tiffany Chairs; stock 250. The picker only checks current
  warehouse stock; stock is deducted only when an event crosses Cutting Stock (Waiting scan in, i.e. loading day).
- **Worst case:** the second event finds out on loading day that only 50 chairs are left.
- **Fix:** reserve at planning time. In Add Item show "Available for these dates = stock − booked by overlapping events"; warn or
  block on shortage with "Rent the rest"; Event Calendar clash list as a weekly check.

### 2. Items added after the cut stage are not deducted
- **Scenario:** Cutting Stock is at Waiting scan in. An admin turns Allow Add Item on for Event running (or adds via Rent/Production/
  transfer-in) and adds 20 more glasses.
- **Worst case:** 20 glasses leave the warehouse without a stock movement → stock and asset value too high; return later adds them
  "back" → stock inflated.
- **Fix:** any line added when the event is already past its cut stage is cut immediately (same notice).

### 3. Stock opname during an event
- **Scenario:** 300 chairs are at a venue. If the event never passed a Cutting Stock stage, the warehouse still lists them. The
  opname counts 0 on the shelf → Admin approves → stock −300. After the event, For Return… does not add them back (not cut).
- **Worst case:** 300 chairs permanently written off.
- **Fix:** opname screen shows "out at events: N" per row and counts against shelf + out; block approving a row whose item is out at
  an event that was not cut.

### 4. For Return defaults to "everything is back"
- **Scenario:** Back now is pre-filled with the full qty; "Confirm return" is one click.
- **Worst case:** the crew confirms before unloading; missing goods are recorded as returned; nobody looks for them.
- **Fix:** Back now starts empty (or at the scanned-out qty); "Everything is back" stays as an explicit button; confirm popup
  shows totals.

### 5. No ending for lost / damaged goods
- **Scenario:** 5 vases broke at the venue; 2 boxes disappeared.
- **Worst case:** event stays Partial Return forever; cut stock stays reserved; asset value includes goods that don't exist.
- **Fix:** per line "Mark lost / damaged" (qty, reason, optional cost to charge the client) → stock movement Lost/Damaged,
  line resolved, event can complete. Report lost value per event.

### 6. Vendor items still out when the event is completed
- **Scenario:** 120 rented charger plates are checked at closing, but nobody presses Mark Returned in the Rented tab.
- **Worst case:** vendor late fees, or the vendor claims the items were never returned.
- **Fix:** For Return includes "Back to vendors" (returned / still out per rental); event is completed only when rentals and
  outsource orders are returned, otherwise Partial Return with reason "vendor items".

### 7. Broken units stay in stock
- **Scenario:** 5 broken chairs written off on an event that was never stock-cut.
- **Worst case:** stock and asset value include broken chairs; next event plans with them.
- **Fix:** write-off creates a Broken stock movement when the line was not cut.

## Medium

### 8. Production for an event counted twice
Mark Done puts the qty in the warehouse **and** adds a line to the event; if the event is past its cut stage, the line is not cut.
**Fix:** cut it immediately (see #2) or deploy straight to the event.

### 9. Transfer ignores the target's rules
A transfer can add items to an event whose current stage has Allow Add Item = False or is past its cut stage.
**Fix:** respect Allow Add Item (or ask for confirmation) and cut immediately when the target is past its cut stage.

### 10. Scan per line, not per piece
One scan marks 40 chairs loaded. **Fix:** per-box (Group QR) or per-piece count; scan shows "scanned 38 / 40".

### 11. "Check all"
One click marks everything checked. **Fix:** Admin-only, with reason, or remove; keep per-item check on mobile.

### 12. Delete / postpone / cancel with running commitments
Delete ignores cut stock, rentals, productions; Postphone / Disable are just stages. **Fix:** guard delete; make Postpone and
Cancel actions that release stock and cancel / reschedule rentals.

### 13. Permissions
Any user can For Return, delete events, open Event Settings by URL. **Fix:** Admin for settings, delete, For Return approval;
Staff for field work; Viewer read-only.

### 14. Changing Event Settings mid-event
Moving Cutting Stock to another stage while events are between the two stages: some events never cut, others cut twice-ish.
**Fix:** warn "N events are between these stages" and apply to new events only, or require Admin confirmation.

### 15. Rental received with a different qty
Vendor delivers 100 instead of 120. Only full receive exists. **Fix:** receive qty (partial) and remaining as "still expected".

## Low

### 16. Alerts
Overdue rentals, event end date passed but still On Going, Partial Return older than N days, incomplete items, low stock before
an upcoming event. **Fix:** Dashboard "Needs attention" + notification bell.

### 17. Recovery
Going back a stage does not restore cut stock; no reopen of a completed event; no undo for a wrong For Return / transfer.
**Fix:** Admin "Reopen" and "Undo last transfer" with reversing movements.

## Suggested order
1. #1, #2, #3 (stock correctness), 2. #4, #5, #6 (closing safety), 3. #7, #8, #9, 4. #12, #13, then the rest.

Out of scope (prototype has no database): persistence of events, event lines, cart, users, moving orders.
